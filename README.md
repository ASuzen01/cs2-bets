# 🎯 CS2 BETS — бот ставок на реальные матчи CS2 для дружеского чата

Python 3.10+ / aiogram 3. Матчи и кэфы берутся из **реальной линии Fonbet**, проходят фильтр
**только тир-1** (IEM, ESL Pro League, BLAST, PGL, мейджоры, Esports World Cup) — квалифайеры,
академии, `H2H 2x2` и прочий мусорный CS2 отсекаются. Ставки — виртуальными монетами,
кэф фиксируется в момент ставки, бот сам закрывает приём по старту и считает результат.

Проверено: **62 теста** (экономика, экспрессы, кнопочный UI, мини-приложение и подпись initData),
smoke-проверка сборки, интеграционный прогон апдейтов через диспетчер, живой запрос линии
(12 матчей IEM Пекин / BLAST Rivals с кэфами), браузерный прогон мини-приложения (ставка и экспресс).

---

## Как это работает

```
Fonbet listBase (gzip JSON)
        │  app/services/fonbet.py — парсинг, фильтр тир-1, кэфы 921/923
        ▼
   matches (SQLite)  ──►  карточки в чаты, кнопки-исходы
        ▲                        │
        │  app/services/sync.py  │ /bet 1 200 1  → ставка с кэфом X
        │  каждые 90 сек:        ▼
        └─ закрытие по старту, расчёт по счёту, выплата «ставка × кэф»
```

## Интерфейс: всё кнопками

Команды знать не нужно — весь путь проходится нажатиями. `/start` открывает меню:

```
🎯 CS2 BETS · баланс
┌ 🎮 Матчи и кэфы   ┐  ┌ 💰 Баланс │ 🎁 Бонус ┐
┌ 🎟 Мой экспресс │ 🏆 Топ ┐  ┌ 📜 История │ 📖 Правила ┐
(админу дополнительно: 🔄 Обновить линию · 📊 Статистика · ⚙️ Автопост)
```

**Ставка:** `🎮 Матчи` → список с пагинацией (`1/2`, `Вперёд ➡️`) → матч →
`1️⃣ Aurora · 1.65` / `2️⃣ G2 · 2.25` → сумма (`50 / 100 / 250 / 500 / 1000`,
`💥 Всё`, `✏️ Своя сумма`) → подтверждение с кэфом и возможной выплатой →
`⬅️ К матчам` / `💰 Баланс` / `🎟 Экспресс`.

**Экспресс:** в карточке матча `🎟 Aurora в экспресс` → корзина с пересчитанным кэфом →
добавляете исходы → `✅ Поставить 250` (или `✏️ Своя сумма`, `🗑 Очистить`).

**Админ:** результат матча подтверждается кнопками `✅ 1` / `2️⃣ …` / `⚪️ Отменить`
(бот присылает их в чат после финала), остальное — в меню.

Текстом вводится только произвольная сумма (после `✏️ Своя сумма`). В группах экраны
приходят отдельными сообщениями, чтобы карточка матча оставалась общей.

### Мини-приложение (Telegram WebApp)

Кроме кнопок в чате есть полноценное приложение. Сейчас оно работает **как локальное превью**
(`python miniapp.py` → `http://localhost:8081`): туннели убраны как нестабильные, а кнопка
`📱 Открыть приложение` в боте появляется только когда задан постоянный `MINIAPP_URL` (см. ниже,
как его получить). Для Telegram-кнопки приложение авторизует игрока по `initData`.

```
python miniapp.py        # http://0.0.0.0:8081 — API + сам интерфейс
```

Экраны: **Матчи** (кэфы Fonbet, тап по кэфу → сумма), **Экспресс** (корзина с пересчётом кэфа),
**Топ**, **История**, **Я** (баланс, бонус, ставки в игре, правила).

| Что важно | Как устроено |
|---|---|
| Одна база | бот и приложение читают/пишут один `data/bot.db`, баланс и история общие |
| Авторизация | `initData` от Telegram, проверка HMAC-SHA256 (`app/services/miniapp.py`), просрочка > 24 ч отсекается |
| API | `GET /api/state`, `POST /api/bet`, `POST /api/express`, `POST /api/bonus`, `GET /api/top`, `GET /api/history`, `GET /health` |
| Интерфейс | один файл `app/web/index.html`: инлайн CSS/JS, без внешних библиотек, тема Telegram, haptic |
| Локальная отладка | `MINIAPP_DEV_USER=<telegram_id>` — вход без Telegram, удобно смотреть в браузере |

Подключение к боту: вписать публичный **https**-адрес в `MINIAPP_URL` — в меню появится кнопка
`📱 Открыть приложение` (WebApp). Без `MINIAPP_URL` кнопка просто не показывается, бот работает как раньше.

> Приложению нужен **постоянный публичный https-адрес** — телефон открывает его сам, туннели
> для этого не годятся (они отваливаются, и приложение висит на загрузке). Два рабочих варианта:
>
> **1) Render (бесплатно, рекомендую).** В репозитории уже лежит `render.yaml`: один сервис
> поднимает и бота (webhook), и мини-приложение — на одном адресе, с одной базой.
> Подключите репозиторий в Render → Blueprint → вписать `BOT_TOKEN` и `ADMIN_IDS` → деплой.
> Адрес будет вида `https://cs2-bets-bot.onrender.com` (он же автоматически попадёт в `MINIAPP_URL`).
>
> **2) Свой VPS / Docker.** `docker build -t cs2-bets .` и `docker run` с `RUN_MODE=webhook`,
> `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET`, `MINIAPP_URL` — приложение и бот поднимутся в одном процессе.
>
> Локально (для отладки в браузере, без публикации): `MINIAPP_DEV_USER=<telegram_id> python miniapp.py`
> и открыть `http://localhost:8081`.

### Экспрессы

Несколько исходов в одной ставке, кэфы перемножаются — как в букмекерской линии.

**Собрать кнопками:** под карточкой матча есть `🎟 Aurora в экспресс` / `🎟 G2 в экспресс`.
Жмёте по нужным исходам в разных матчах — бот показывает корзину и итоговый кэф. Затем
кнопка `✅ Поставить 250` (или `✏️ Своя сумма`).

**Одной командой:** `/express 200 1:1 4:2` — 200 монет на то, что матч #1 возьмёт первая
команда, а матч #4 — вторая.

Правила расчёта:

| Ситуация | Итог |
|---|---|
| все исходы зашли | выплата `ставка × кэф1 × кэф2 × …` |
| хотя бы один не зашёл | экспресс проигран, выплата 0 (считается сразу, не дожидаясь остальных) |
| матч отменён (`/voidmatch`) | его кэф = 1.0, остальные пересчитываются |
| отменены все матчи | полный возврат ставки |

Лимиты: минимум 2 исхода, максимум 6 (`MAX_EXPRESS_LEGS`), потолок итогового кэфа 40
(`MAX_EXPRESS_ODDS`). Один и тот же матч нельзя взять дважды в один экспресс; одиночная
ставка и экспресс на один матч — можно.

### Деньги и кэфы

- Ставка: `выплата = ставка × кэф` при угаданном исходе, `0` при ошибке.
- Кэф фиксируется в момент ставки — линия может сдвинуться, ваша ставка уже не меняется.
- Приём ставок закрывается автоматически в момент начала матча.
- `ODDS_MODE=real` — кэфы как у букмекера (с маржой ≈5 %). `ODDS_MODE=fair` — маржа убирается,
  сумма вероятностей нормализуется к 1 (монеты в чате живут дольше).
- Матч отменён → `/voidmatch`, ставки возвращаются полностью.

## Локальный запуск

```bash
cd telegram-bot
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env      # вписать BOT_TOKEN и ADMIN_IDS
python bot.py
```

Через несколько секунд в логах:

```
Синк линии запущен, период 90 сек
Линия: 12 матчей тир-1 (новых 12, закрыто 0, рассчитано 0, ждут подтверждения 0)
```

Дальше в Telegram: `/start` → кнопка **🎮 Матчи и кэфы** → матч → исход → сумма.

> **Групповые чаты:** ставки полностью на кнопках, поэтому privacy mode можно оставить
> включённым. Disable (`/setprivacy`) нужен только если хотите вводить произвольную сумму
> обычным сообщением в группе, а не в личке с ботом.
> Автопост матчей включается сам для групповых чатов, где бот получил хоть одно сообщение
> (`/autopost` — выключить).

## Настройка тир-1 и кэфов

```env
# что считаем тир-1 (подстрока в названии турнира Fonbet)
TIER1_INCLUDE=IEM,ESL Pro League,ESL One,BLAST Premier,BLAST Rivals,BLAST Bounty,BLAST Open,PGL,Major,World Cup
# что режем даже внутри тир-1
TIER1_EXCLUDE=Qualifier,Квалификац,Academy,Women,H2H,1x1,2x2,Showmatch,CCT
ODDS_MODE=real          # real | fair
SYNC_INTERVAL=90
```

Так отсекаются, например: `Counter-Strike. H2H CS. 2X2. Москва. Bo1`,
`Counter-Strike. European Pro League. Bo3`, `Counter-Strike. NODWIN Clutch. Bo3`,
`Counter-Strike. Elisa Open Suomi. Bo3`, `Counter-Strike. IEM Пекин. Open Qualifier. Bo3`,
и остаются `Counter-Strike. IEM Пекин. Групповой этап. Bo3`, `Counter-Strike. BLAST Rivals...`.

Расчёт результата:

1. Пока матч в линии, бот читает счёт (`eventMiscs.score1/score2`, флаг `finished`).
2. Счёт серии (2:0, 2:1, 3:2 для Bo5) → автоматическая выплата и сообщение в чат.
3. Если счёт неоднозначный (в линии видны раунды карты) или матч ушёл из линии без результата —
   бот присылает карточку с кнопками `🏆 Aurora / 🏆 G2 / 🚫 не состоялся`: админ подтверждает
   исход одним нажатием (или `/win 12 1`).

## Деплой: Render + Neon (бесплатно, без карты)

Один сервис поднимает **бота (webhook) и мини-приложение** на одном адресе, база живёт
в бесплатном Postgres от Neon — поэтому балансы не теряются при перезапуске.

**Шаг 1. База (Neon, 2 минуты).** [neon.tech](https://neon.tech) → регистрация через GitHub →
**Create project** (регион ближе к вам, например Frankfurt) → скопировать **Connection string**
вида `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
Схему создавать руками не нужно: бот сделает таблицы сам при первом запуске.

**Шаг 2. Код (GitHub).** Залейте папку `telegram-bot` в репозиторий (`.env` не коммитить!).
Удобно:

```bash
cd telegram-bot
git init && git add . && git commit -m "cs2 bets"
git remote add origin https://github.com/<вы>/cs2-bets.git && git push -u origin main
```

**Шаг 3. Render (1 клик).** [render.com](https://render.com) → **New → Blueprint** → выбрать
репозиторий (в нём уже лежит `render.yaml`) → вписать секреты:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен из @BotFather |
| `ADMIN_IDS` | ваш telegram id |
| `DATABASE_URL` | строка подключения из Neon |

Остальное Render подставит сам: `RUN_MODE=webhook`, `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET`,
`MINIAPP_URL` (адрес сервиса) — кнопка «📱 Открыть приложение» появится в меню бота автоматически.

**Шаг 4. Проверка.** `https://<сервис>.onrender.com/health` → `{"ok": true, "mode": "webhook"}`,
`https://<сервис>.onrender.com/` → мини-приложение. Дальше `/start` в боте.

**Шаг 5. Перенести текущие балансы (необязательно).** В папке проекта:

```bash
DATABASE_URL='postgresql://...neon.tech/neondb?sslmode=require' \
    python scripts/migrate_to_postgres.py --dry-run   # посмотреть
DATABASE_URL='...' python scripts/migrate_to_postgres.py  # перенести игроков, чаты, историю
```

Ставки и экспрессы не переносятся — они живут вместе с матчами, а матчи на новом хостинге
заново приедут из линии Fonbet.

**Ограничения free-плана (честно):** сервис засыпает через ~15 минут без запросов, первый заход
после сна — 30–50 секунд (лечится бесплатным пингом `/health` раз в 10 минут через cron-job.org
или UptimeRobot; пинг ещё и не даёт пропускать обновление линии). Neon free: 0.5 ГБ и автосон
базы, для дружеского чата хватает с запасом.

### Локально

Ничего не меняется: `python bot.py` (SQLite) и `python miniapp.py` (порт 8081). Если хочется
проверить Postgres-путь локально — `DATABASE_URL=postgresql://...` и те же команды.

Тесты на двух движках:

```bash
pytest -q                                    # SQLite
TEST_DATABASE_URL='postgresql://...' pytest -q   # тот же набор на Postgres
```

### Варианты вместо Render

- **Свой VPS / Oracle Always Free** — `docker build -t cs2-bets .` и запуск с
  `RUN_MODE=webhook`, `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET`, `MINIAPP_URL`; база может остаться SQLite на диске.
- **Koyeb / любой Docker-PaaS** — тот же образ, переменные те же.

## Источник данных: важные оговорки

- Fonbet **не публикует официальный контракт API**. Эндпоинт `events/listBase` — публичная линия
  сайта, он может измениться в любой момент. Весь доступ изолирован в `app/services/fonbet.py`:
  заменить источник (легальный odds-API, PandaScore, собственный агрегатор) = переписать один
  класс, логика ставок и выплат не трогается.
- Автоматический парсинг чужого сайта может нарушать правила букмекера. Бот использует только
  публичные данные линии, ничего не ставит и не авторизуется, но ответственность за использование
  — на владельце бота. Для приватной игры с друзьями на виртуальные монеты риск минимальный.
- Кэфы — интеллектуальная собственность букмекера: не выводите их в публичный продукт/агрегатор.
- Вся игра — на виртуальные монеты: пополнения, выводы и реальные ставки отсутствуют.

| `DROP_PENDING_UPDATES` | false | выбрасывать накопленные апдейты при старте |
| `THROTTLE_SECONDS` | 0.4 | анти-спам |
| `LOG_LEVEL` | INFO | уровень логов |

## Если что-то не работает

1. **«Нет матчей»** → `/sync` (админ) и смотрите лог: строка `Линия: N матчей тир-1`.
   `N=0` — либо линия пуста, либо фильтр слишком строгий (`TIER1_INCLUDE`), либо хостинг не видит Fonbet.
2. **Бот молчит в Telegram** → `pending_update_count` в `getWebhookInfo` растёт? Тогда апдейты
   не доходят: чаще всего виноваты долгие long-poll запросы за NAT/прокси — `POLLING_TIMEOUT=10`
   и перезапуск. Смотрите строки `Update id=… is handled` в логах.
3. **Результат не пришёл сам** → бот пришлёт карточку с кнопками подтверждения.
   Ручной ввод: `/win 12 1`, отмена: `/voidmatch 12`.
4. **Бот «не откликается», хотя процесс жив** → почти всегда запущено несколько экземпляров:
   Telegram отдаёт апдейты только одному `getUpdates`, остальные получают `409 Conflict`,
   и бот выглядит мёртвым. Проверьте и убейте дубли:

   ```bash
   ps -eo pid,etime,cmd | grep "bot[.]py"   # должно быть ровно одна строка
   pkill -f "venv/bin/python bot.py"        # затем запустить один
   ```

   С версии с кнопочным UI бот сам берёт `flock` на `data/bot.lock`: второй экземпляр
   завершается с кодом 2 и пишет `Уже запущен другой экземпляр бота` — 409 больше не
   возникает, даже если случайно стартовать дважды.
5. **Мини-приложение висит на загрузке** → проверьте адрес: `curl -s -o /dev/null -w "%{http_code}" $MINIAPP_URL/api/health`
   (`200` — сервер жив). На бесплатном хостинге первый запрос после сна бывает медленным (до 30–50 с) —
   это нормально, дальше работает быстро.
6. **Мини-приложение не открывается** → откройте адрес из `MINIAPP_URL` в браузере:
   если и там пусто — сервис не задеплоен или уснул (free-план просыпается до 50 с, откройте ещё раз).
7. **Нажали кнопку — «Кнопка устарела»** → экран из старого сообщения после перезапуска бота.
   Откройте `/menu` и продолжайте с нового экрана.
