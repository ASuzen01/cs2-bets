# 🎯 CS2 BETS — ставки на реальные матчи CS2 внутри Telegram

Python 3.10+ / aiogram 3 / aiohttp. Матчи и кэфы берутся из **реальной линии Fonbet** и проходят
фильтр **только тир-1** (IEM, ESL Pro League, BLAST, PGL, мейджоры, Esports World Cup) — квалифайеры,
академии, `H2H 2x2` и прочий мусорный CS2 отсекаются. Ставки — виртуальными монетами, кэф
фиксируется в момент ставки, приём закрывается по старту, результат считается автоматически.

**Бот в Telegram — это только вход.** В нём одна кнопка «📱 Открыть приложение» и служебные
команды; все ставки, экспрессы, баланс, бонус, история и топ живут в мини-приложении.
Меню-кнопка «Ставки» слева в строке ввода открывает приложение откуда угодно.

Живёт на бесплатном Render + Neon: **https://cs2-bets-bot.onrender.com**

## Как это работает

```
Fonbet listBase (gzip JSON)
        │  app/services/fonbet.py — парсинг, фильтр тир-1, кэфы 921/923
        ▼
   matches (Postgres / SQLite)  ◄──  бот (webhook) + мини-приложение, один процесс, одна база
        ▲                        │
        │  app/services/sync.py  │ POST /api/bet  → ставка с зафиксированным кэфом
        │  каждые 90 сек:        ▼
        └─ закрытие по старту, расчёт по счёту, выплата «ставка × кэф»
```

## Мини-приложение (Telegram WebApp)

Один файл `app/web/index.html`: инлайн CSS/JS, без внешних библиотек, тема Telegram, haptic.

| Что важно | Как устроено |
|---|---|
| Одна база | бот и приложение читают/пишут один и тот же Postgres (или SQLite локально) |
| Авторизация | `initData` от Telegram, HMAC-SHA256 (`app/services/miniapp.py`), просрочка > 24 ч отсекается |
| API | `GET /health`, `GET /`, `GET /api/state`, `POST /api/bet`, `POST /api/express`, `POST /api/bonus`, `GET /api/top`, `GET /api/history` |
| Защита | без валидной подписи любой `/api/*` отдаёт `401` |
| Локальная отладка | `MINIAPP_DEV_USER=<telegram_id> python miniapp.py` → `http://localhost:8081` в браузере |

## Экспрессы

Несколько исходов в одной ставке, кэфы перемножаются — как в букмекерской линии.

| Ситуация | Итог |
|---|---|
| все исходы зашли | выплата `ставка × кэф1 × кэф2 × …` |
| хотя бы один не зашёл | экспресс проигран, выплата 0 (считается сразу, не дожидаясь остальных) |
| матч отменён | его кэф = 1.0, остальные пересчитываются |
| отменены все матчи | полный возврат ставки |

Лимиты: минимум 2 исхода, максимума и потолка кэфа нет (`MAX_EXPRESS_LEGS=0`, `MAX_EXPRESS_ODDS=0`)
(`MAX_EXPRESS_ODDS`). Один матч нельзя взять дважды в один экспресс.

## Деньги и кэфы

- Ставка: `выплата = ставка × кэф` при угаданном исходе, `0` при ошибке.
- Кэф фиксируется в момент ставки — линия может сдвинуться, ваша ставка уже не меняется.
- Приём ставок закрывается автоматически в момент начала матча.
- `ODDS_MODE=real` — кэфы как у букмекера (с маржой ≈5 %). `ODDS_MODE=fair` — маржа убирается.
- Матч отменён → админ отменяет его в боте, ставки возвращаются полностью.

## Настройка тир-1 и кэфов

```env
TIER1_INCLUDE=IEM,ESL Pro League,ESL One,BLAST Premier,BLAST Rivals,BLAST Bounty,BLAST Open,PGL,Major,World Cup
TIER1_EXCLUDE=Qualifier,Квалификац,Academy,Women,H2H,1x1,2x2,Showmatch,CCT

SYNC_INTERVAL=45
STALE_MATCH_HOURS=12
LIVE_BETTING=true       # ставки по ходу матча (false — приём только до старта)
```

Отсекаются, например: `Counter-Strike. H2H CS. 2X2. Москва. Bo1`, `Counter-Strike. European Pro
League. Bo3`, `Counter-Strike. IEM Пекин. Open Qualifier. Bo3`; остаются
`Counter-Strike. IEM Пекин. Групповой этап. Bo3`, `Counter-Strike. BLAST Rivals. Групповой этап. Bo3`.

Расчёт результата:

1. Пока матч в линии, бот читает счёт (`eventMiscs.score1/score2`, флаг `finished`).
2. Счёт серии (2:0, 2:1, 3:2 для Bo5) → автоматическая выплата и уведомление игрокам.
3. Если счёт неоднозначный или матч ушёл из линии без результата — бот присылает админу
   карточку с кнопками `🏆 Aurora / 🏆 G2 / 🚫 не состоялся`. Список таких матчей — `/results`.

## Деплой: Render + Neon

Прод сейчас работает по этой схеме: один сервис (`render.yaml`, Docker) поднимает бота в
режиме webhook и мини-приложение на одном адресе, база — Postgres в Neon.

```bash
# 1. база: neon.tech → Create project → скопировать Connection string
# 2. код:  git push в GitHub
# 3. Render: New → Blueprint → выбрать репозиторий → вписать BOT_TOKEN, ADMIN_IDS, DATABASE_URL
```

Три переменные, которые задаются руками (`sync: false` в `render.yaml`):

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен из @BotFather |
| `ADMIN_IDS` | ваш telegram id |
| `DATABASE_URL` | строка подключения Neon целиком |

`WEBHOOK_BASE_URL` и `MINIAPP_URL` должны быть **полными адресами** —
`https://<сервис>.onrender.com` (не имя сервиса), `WEBHOOK_SECRET` — только `A-Z a-z 0-9 _ -`.
Подробный чек-лист с реальными граблями: `docs/deploy-render-neon.md`.

Перенос балансов из локальной SQLite:

```bash
DATABASE_URL='postgresql://...' python scripts/migrate_to_postgres.py --source data/bot.db --dry-run
DATABASE_URL='postgresql://...' python scripts/migrate_to_postgres.py --source data/bot.db
```

**Ограничения free-плана:** сервис засыпает через ~15 минут без запросов, первый заход после
сна — 30–50 секунд (лечится пингом `/health` раз в 10 минут через cron-job.org или UptimeRobot).

## Источник данных: важные оговорки

- Fonbet **не публикует официальный контракт API**. Эндпоинт `events/listBase` — публичная линия
  сайта, он может измениться в любой момент. Весь доступ изолирован в `app/services/fonbet.py`:
  заменить источник = переписать один класс, логика ставок и выплат не трогается.
- Автоматический парсинг чужого сайта может нарушать правила букмекера. Бот использует только
  публичные данные линии, ничего не ставит и не авторизуется; ответственность за использование
  — на владельце бота. Для приватной игры с друзьями на виртуальные монеты риск минимальный.
- Кэфы — интеллектуальная собственность букмекера: не выводите их в публичный продукт.
- Вся игра — на виртуальные монеты: пополнений, выводов и реальных ставок нет.

## Футбол: Лига Чемпионов и еврокубки

Матчи берутся из той же линии Fonbet, что и CS2 (фильтр `FOOTBALL_INCLUDE`, по
умолчанию Лига Чемпионов, Лига Европы и Лига Конференций).

**Откуда кэфы.** По футбольному матчу Fonbet отдаёт 400+ коэффициентов, но без
словаря: приходят числовые id факторов и параметры вида `pt="+2.5"`. Угадывать,
что `f=2327` — это «точный счёт 2:3», нельзя: ошибка в один номер даёт неверную
подпись и неверный расчёт. Поэтому из линии берётся то, что читается однозначно —
**исход 1X2** (факторы 921/922/923, те же, что в CS2) — а вся остальная роспись
считается из него моделью Пуассона:

* вероятности книги нормируются (маржа убирается);
* подбираются интенсивности голов хозяев и гостей так, чтобы модель дала те же П1/X/П2;
* по матрице счетов считаются все производные рынки с нашей маржой 5 %.

Так 1X2 и тотал не могут противоречить друг другу, расчёт однозначен, и линия не
зависит от того, перетасует ли Fonbet свою нумерацию факторов. Никакого скрейпинга
пяти контор: чужие сайты отдают данные под антиботом, а «кэфы из Бетбума»,
пропущенные через парсер, — это гарантированные дырки в линии.

**Live CS2.** Кэфы Fonbet по ходу матча иногда снимает — тогда событие уходит из выдачи
вместе с кэфами. Матч при этом не пропадает: он остаётся live, играет по последним
известным кэфам, а счёт по картам продолжает обновляться (счёт берём даже без кэфов).
Ставки в лайве принимаются, пока не истёк формат матча: Bo1 — 90 минут, Bo3 — 170,
Bo5 — 260. Если серия уже выиграна (2:0 в Bo3) и матч пропал из линии на 5 минут —
рассчитываем по последнему счёту. Если формат истёк, а результата нет — матч уходит
в «ждёт результата» и ждёт фактический исход. На карточке виден и счёт по картам,
и счёт каждой карты («Карта 2 · 6:8»).

**Как считается CS2: карты и раунды.** Игра состоит из карт, для победы в игре
нужно взять нужное их число: Bo1 — одну, Bo3 — две, Bo5 — три. Карта идёт до
13 раундов; при 12:12 начинается овертайм — блок из шести раундов, в котором надо
взять четыре. Если блок закончился 15:15, играется следующий такой же блок, и так
до победы. Отсюда корректные финальные счёта карты: 13:N (N ≤ 11), 16:12–16:14,
19:15–19:17, 22:18–22:20 и так далее. Всё остальное (13:12, 15:14, 12:12, 9:3) —
идущая карта. Правила лежат в `app/services/cs2_rules.py`, их используют и синк,
и админские команды, и ручные результаты.

**Ставки на карту.** Карта рассчитывается отдельно от матча и по счёту раундов:
доиграли до победы — ставка играет; на карте не было ни одного раунда (серия
закончилась раньше, например 2:0 в Bo3) — возврат. Карта, у которой счёт есть,
а победителя по нему не видно (линия оборвалась на 9:3), остаётся в «ждём» со
ставками в игре: её добивает админ командой `/maps`. Приём ставок на карту зависит
от самой карты, а не от статуса серии: пока карта `open`/`live` и кэф есть, ставить
в лайве можно, даже если серия числится в «ждёт результата». На карточке рядом
с номером карты видно состояние: счёт, «готово», «ждём» или «возврат».

**Сыгранные матчи возвратом не рассчитываются.** Если ставки на матч были, матч
игрался — значит исход будет: событие закрывается по победителю, выигрыши
выплачиваются, игрокам уходят уведомления. Возврат (`cancelled`) остаётся только
для матчей, которые реально не состоялись, — и технически допустим лишь там, где
на матче нет ни одной ставки. Матч без счёта висит в `awaiting` до тех пор, пока
результат не появится: из счёта по картам, из live-счёта или из файла
`data/manual_results.json` (см. ниже).

**Ручные результаты — `data/manual_results.json`.** Fonbet после финального свистка
счёт не отдаёт, поэтому недостающие исходы вписываются руками и применяются при
старте бота:

```json
[
  {"teams": ["Team Liquid", "TYLOO"], "score": "2:0", "winner": "a",
   "note": "IEM Beijing 2026, нижняя сетка"}
]
```

`winner` — `a` (первая команда) или `b` (вторая), порядок команд в `teams` значения
не имеет. Если матч был ошибочно отменён с возвратом, он пересчитывается по факту:
возвраты снимаются, выигрыш выплачивается, уведомления уходят. Обработка
идемпотентна — рассчитанный матч повторно не трогается, файл можно не чистить.
Точечно то же самое делает админ командой `/recount ID 1|2`.

Каталог `data/` лежит в `.gitignore`, поэтому файл с результатами нужно добавлять
в репозиторий принудительно: `git add -f data/manual_results.json`.

**Как считается футбольный матч.** Пока матч в линии, счёт обновляется каждые 45 секунд.
Завершённые события Fonbet выбрасывает из линии, а `/events/event` по ним возвращает
пустоту — финальный счёт после матча взять негде.

**По последнему live-счёту считать нельзя:** гол на 90+4 или в добавленное время
меняет исход, а мы бы уже расплатились по счёту с 90-й минуты. Поэтому финальный
счёт берётся из внешнего фида результатов (`app/services/results.py`, публичный
фид livescore):

* матч сопоставляется по английским названиям команд (`team_a_en`/`team_b_en`,
  их отдаёт Fonbet при `lang=en`) и дате старта ±сутки;
* для исхода, тоталов и фор берётся счёт **за 90 минут** (`Tr1OR`/`Tr2OR`), а не
  счёт с овертаймом: эти рынки считаются по основному времени;
* статусы: `FT`/`AET`/`AP` — матч сыгран, `Postp.`/`Canc.`/`Aband.` — не состоялся
  (только здесь возвращаются ставки), всё остальное — ждём.

Пока фида результата нет, матч висит в «ждёт результата» (`awaiting`), ставки в игре,
и синк переспрашивает фид раз в 10 минут.

**Перепроверка.** При старте бота (и по команде `/recheck [часов]`) свежие расчёты
сверяются с фактами заново: футбол — с фидом результатов, CS2 — со счётом по картам.
Если факт расходится с базой, матч пересчитывается (выплаты откатываются, ставки
считаются заново), а админу приходит отчёт со списком исправлений. Совсем нет результата — админ считает
вручную: `/recount` для CS2, счёт вида `2:3` в `data/manual_results.json` — для
футбола (уже посчитанный матч при этом пересчитывается и выплаты откатываются).

**Фильтр по турнирам.** Над линией есть выпадающий список турниров с количеством
матчей (для футбола — ЛЧ/ЛЕ/ЛК и стадии плей-офф, для CS2 — свои турниры). Выбор
запоминается отдельно для каждого вида спорта, рядом появляется кнопка «Сбросить».

**Что в линии (63+ рынка на матч):**

| Группа | Рынки |
| --- | --- |
| Исход | П1, X, П2 — реальные кэфы книги |
| Двойной шанс | 1X, 12, X2 |
| Тотал голов | ТБ/ТМ 0.5, 1.5, 2.5, 3.5, 4.5 |
| Обе забьют | Да, Нет |
| Фора | Ф1/Ф2 ±0.5, ±1.5, ±2.5 |
| Тотал команды | ИТ1 и ИТ2 больше/меньше 0.5, 1.5, 2.5 |
| Точный счёт | 0:0…4:4 и «другой счёт» |
| Проход дальше | только в плей-офф (1/8, 1/4, финал…) |

**Правила расчёта.** Матч считается по финальному счёту из линии.

* Тоталы и форы — только «половинные» (2.5, -1.5), поэтому возвратов по ним не бывает.
* «Проход дальше» считается по основному времени. Если матч закончился вничью,
  кто прошёл — по счёту не видно: такие ставки **возвращаются** целиком.
* «Проход дальше» есть только там, где пара решается одним матчем (финал,
  одноматчевые стадии). В двухматчевых парах рынка нет: победитель первого матча
  ещё ничего не значит, и считать проход по одной игре было бы неправдой.
* **Live.** На исход 1X2 ставки идут во время матча — кэфы живые, прямо из линии.
  Производную роспись (тоталы, форы, счёт) в live не показываем: она считается от
  предматчевых кэфов и закрывается на старте.
* Экспрессы собираются только из исходов 1X2 (у них есть однозначный победитель).

## Резервные копии

Что защищает данные:

1. **Neon** — встроенное восстановление на момент времени. На бесплатном плане окно
   всего 6 часов (до 1 ГБ изменений), поэтому это защита от «ой, удалил», а не от
   потери проекта. Ручной снапшот на бесплатном плане — один.
2. **Свой дамп каждый час.** Бот сам снимает копию всех таблиц (gzip + JSON),
   отправляет файл в личку админу (без звука, чтобы не будить) и пишет отметку в `backup_log`. Файл живёт в
   облаке Telegram — то есть вне Render и Neon. Размер нашей базы — единицы килобайт,
   лимит Telegram в 20 МБ далеко.
3. **Ручной дамп** — `/backup` в боте или `python scripts/backup_db.py`.

Восстановление:

```bash
python scripts/restore_db.py backups/file.json.gz          # покажет содержимое и состав
python scripts/restore_db.py backups/file.json.gz --yes    # восстановит
```

Или просто пришлите файл `.json.gz` боту в личку: он покажет, что внутри, сколько
игроков и ставок, попросит подтверждение кнопкой и **перед затиранием сам пришлёт
текущее состояние** отдельным файлом. Дамп проверяется по контрольным числам —
битый или чужой файл не примется.

Дамп переносим между SQLite и Postgres: можно развернуть копию локально и посмотреть,
что произошло. `backups/` и `*.json.gz` в `.gitignore` — база в публичный репозиторий
не попадает.

## Если что-то не работает

1. **В боте нет кнопки приложения** → пустой `MINIAPP_URL`: `/start` пришлёт текст без кнопки,
   `/help` прямо скажет, чего не хватает. Задайте `https://<сервис>.onrender.com` и перезапустите.
2. **«Нет матчей» в приложении** → смотрите логи: строка `Линия: N матчей тир-1`. `N=0` — линия
   пуста, фильтр `TIER1_INCLUDE` слишком строгий или хостинг не видит Fonbet.
3. **Приложение висит на загрузке** → `curl -s $MINIAPP_URL/health` должен вернуть `{"ok": true}`.
   После сна free-плана первый запрос занимает 30–50 с — это нормально.
4. **`401` на `/api/state`** → нет подписи `initData`: приложение открыто не из Telegram
   (в браузере нужен `MINIAPP_DEV_USER`).
5. **Бот «не откликается», хотя процесс жив** → запущено несколько экземпляров: Telegram отдаёт
   апдейты только одному, остальные получают `409 Conflict`. Бот берёт `flock` на `data/bot.lock`,
   второй экземпляр сам завершается с кодом 2.
6. **Результат не пришёл сам** → `/results` покажет матчи, ждущие подтверждения, с кнопками.
7. **Данные пропали после перезапуска** → не задан `DATABASE_URL`, приложение пишет в SQLite
   внутри контейнера, а он пересоздаётся. Проверьте переменную на Render.
