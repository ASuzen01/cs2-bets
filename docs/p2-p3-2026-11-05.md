## P2 — продукт: чтобы возвращались

### Задания дня
Три задания из четырёх, набор сдвигается каждый день (`app/services/quests.py`):

| Задание | Награда |
|---|---|
| Сделай любую ставку | 100 🪙 |
| Сыграй раунд в рулетку или кости | 100 🪙 |
| Собери экспресс из двух исходов | 200 🪙 |
| Забери бонус или крутни колесо | 150 🪙 |

- прогресс двигается сам из `place_bet`, `place_express`, `play_casino`, бонусов и колеса
  (хук `_bump_quest` внутри той же транзакции — никаких лишних записей);
- таблица `quests(user_id, day, code, progress, target, reward, claimed_at)` создаётся лениво,
  поэтому игрок, который ни разу не открыл бонусы, всё равно получит прогресс за ставку;
- `POST /api/quest {code}` — забрать награду; повторно нельзя (проверка в транзакции);
- карточка «Задания дня» на экране бонусов: прогресс-бар, сумма награды, кнопка «Забрать»;
- точка на колокольчике теперь учитывает и готовые задания.

### Серия дней (streak)
- `users.streak_days` + `users.bonus_day`; забрал вчера — серия продолжается, пропустил день — начинается заново;
- бонус: `+10 %` за каждый день серии, потолок `+50 %` (5-й день и дальше);
- на карточке бонуса: «🔥 3 дня подряд · +20 % к бонусу», в `/api/state` — `streak`, `next_streak`, `bonus_percent`.

### Статистика игрока
`GET /api/stats` и блок «Моя статистика» на экране «Я»: винрейт, ROI, оборот,
лучшая выплата, раунды в играх с итогом, любимый турнир.

### «Повторить ставку»
Кнопка в карточке ставки (одиночные на исход матча): открывает лист суммы с тем же
матчем и стороной. Матч ушёл из линии — кнопка неактивна с подписью «Матч уже не в линии».

### Уведомление о расчёте
После расчёта ставки игрок видит тост «Ставка зашла: +240 🪙» (или «N ставки рассчитаны:
итог −150 🪙»), даже если он на другом экране. Список увиденных хранится в localStorage,
на первом запуске — без шквала тостов.

### Избранные команды
Звезда ☆/★ в карточке матча и фильтр «★ Мои · N» в строке фильтров (локально, без сервера).

### События для аналитики
Таблица `events` + `db.log_event()`: пишутся начисления за задания. Дальше туда же
просятся `bet_placed`, `bonus_claimed`, `casino_spin` — код готов, нужен только вызов.

## P3 — инженерия и надёжность

- **Rate limit** (`app/web/limits.py`): скользящее окно по (игрок, путь), отдельные лимиты
  для ставок (20/мин), казино (40/мин), колеса (8/мин) и т. д.; ответ `429` + `Retry-After`.
- **Потолок ставки на сервере**: `MAX_BET` (по умолчанию 5000) проверяется в `/api/bet`
  (включая футбольные и хоккейные рынки) и `/api/express`; отдаётся в `/api/state.limits.max_bet`.
- **Честный `/health`**: пинг базы (`SELECT` по meta), `db: "ok"`, `last_sync_at`,
  `last_sync_age_seconds`, `feed_stale`; при недоступной базе — `503`. `sync` пишет метку
  `last_sync_at` после каждого успешного обновления линии.
- **`/metrics`**: счётчики запросов, ошибок, отказов по лимиту, ставок, экспрессов, раундов,
  бонусов, разбивка по путям — в текстовом формате, читается глазами и Prometheus.
- **Алерт при 500**: middleware ловит исключение и пишет админу в Telegram
  (не чаще раза в 5 минут), в вебхук-режиме подключается в `bot.py`.
- **Postgres**: в транзакции берётся `pg_advisory_xact_lock` — если когда-нибудь будет
  два инстанса, они не будут писать одновременно; на SQLite поведение не меняется.
- **Проверка бэкапа**: `scripts/check_backup.py` разворачивает дамп в отдельную базу,
  сверяет число строк по ключевым таблицам и сравнивает леджер с суммой балансов.
  Запускается без аргументов (свежий дамп) или по файлу; код возврата 1 при проблеме.
- **CI**: `.github/workflows/ci.yml` — `ruff check app bot.py tests scripts` + `pytest` на push и PR.

## Найденный по ходу баг

`init()` выполнялся **дважды**: скрипт подключён с `defer`, и условие
`if (document.readyState !== "loading") init()` срабатывало сразу, а потом ещё раз
на `DOMContentLoaded`. Из-за этого каждый обработчик висел в двух экземплярах:
переключатели возвращались назад, фильтры «туда-обратно», лишние запросы.
Исправлено: флаг `started`, плюс `once()` для слушателей на статических кнопках
(они раньше добавлялись заново при каждой перерисовке).

## Что осталось сознательно не сделано

- **Колесо с 8 пустыми секторами** — заявленная механика, экономику не меняли.
- **Пул соединений Postgres**: сейчас одно соединение на процесс и advisory-замок.
  Для настоящего масштабирования нужен `psycopg_pool` + `SELECT ... FOR UPDATE` по игроку —
  это отдельная задача с прогоном всего набора на Postgres (`TEST_DATABASE_URL`).
- **Шаринг купона картинкой** — требует canvas-рендера купона; текстовый шаринг через
  `tg.openTelegramLink` проще, но выигрыш меньше. Отложено.
