Проверено в браузере (390 px и 320 px, dev-режим): JS-ошибок нет.

## P0 — то, что били по доверию

### 1. Параллельные ставки падали с 500 — закрыто (`5ab4145`)
На процесс одно соединение с базой, поэтому два одновременных `BEGIN` роняли запрос
с «cannot start a transaction within a transaction».

- `Database.transaction()` и новый `Database._write()` идут под общим `asyncio.Lock`;
- вложенный `transaction()` из той же задачи продолжает внешнюю транзакцию, а не открывает вторую;
- если перед `BEGIN` на соединении всё же висит транзакция — она откатывается (страховка);
- 19 мест `conn.execute(...) + commit()` переведены на `_write`; один незакоммиченный
  `UPDATE match_maps` был источником висящей транзакции.

Проверка: 4 параллельные ставки по 50 при балансе 150 → 3 приняты, одна «Недостаточно монет»,
двойного списания нет, 500 больше нет. Регрессия — `tests/test_concurrency.py`.

### 2. Ставка на уже начавшийся матч — закрыто
`status='open'` + `start_time` в прошлом (фид не успел перевести матч в live) больше не принимается:
`_betting_refusal` отказывает «Матч уже начался — ставки не принимаются». Live-ставки при
`live_betting` работают как раньше.

Чтобы игрок не узнавал об этом из ошибки, в карточке:
кэфы такого матча неактивны (`.odd.off`, title «Матч уже начался»),
кнопка «Добавить в экспресс» неактивна с подписью «матч начался».

### 3. Двойной тап списывал дважды — закрыто
Клиент присылает `token` (одна метка на попытку: лист ставки, экспресс, раунд в игре).
Сервер пишет токен в новую таблицу `bet_requests (user_id, channel, token, bet_id)`:
первый запрос выигрывает, повторный отдаёт результат первой ставки — без второго списания.

- `place_bet(..., token=)`, `place_express(..., token=)`, `play_casino(..., token=)`;
- старый клиент без токена работает как раньше;
- токен сбрасывается только после успешного ответа: если связь оборвалась, ретрай безопасен.

Проверка API: 4 параллельных `POST /api/bet` с одним токеном → четыре `200` и **одно** списание
(1000 → 900); два разных токена → два списания. Регрессия — `tests/test_guards.py`.

### 4. Нулевой баланс — закрыто
- тап по кэфу при балансе меньше минимальной ставки открывает лист «Не хватает монет»
  («нужно минимум 10 🪙, на балансе 0 🪙») с кнопкой «К бонусам», а не лист «Ставка: 10 · выигрыш: 33»;
- то же для экспресса и для игр («Крутить» при нехватке монет ведёт в тот же лист);
- тап по ежедневному бонусу в режиме ожидания теперь отвечает «Бонус уже получен — следующий через 3 ч 12 мин»
  вместо пустого тоста.

### 5. Игры: результат чужой игры на экране — закрыто
- результат хранится по каждой игре отдельно (`state.casinoResults`), на экран попадает только свой;
- ушли с вкладки во время вращения — результат приходит тостом с названием игры
  («Рулетка · 17 — чёрное · −50 🪙»), а на вкладке игр остаётся корректный результат;
- смена игры посреди раунда блокируется тостом «Дождись конца раунда»;
- блокировка кнопок переживает перерисовку экрана (`if (state.casinoBusy) lockTable(true)`).

## P1 — полировка

- **«Поставить экспресс» при одном исходе** неактивна и подписана «Добавь ещё один исход»
  (раньше узнавали по ошибке сервера).
- **Тост «Максимум за раунд»** больше не всплывает поверх карточек: сумма просто ужимается до лимита,
  а предел виден в подписи под полем. Тосты живут 2.4 с и не растягиваются на всю ширину.
- **Шапка на 320 px**: подпись под брендом переносится на две строки вместо «локальны…»,
  баланс и маскот ужимаются, ничего не режется посередине слова.
- **«Топ»**: своя строка подсвечивается, а если игрок вне десятки — под списком блок «Ваше место» с его позицией.
- **История операций**: заголовки дней («Сегодня», «Вчера», «05 ноября»).
- **Пустые состояния**: у истории и топа есть кнопка («К матчам»), а не только текст.

## Что сознательно не менял

- **Колесо: 8 пустых секторов из 24 (33 %)** — это заявленная механика (правила в приложении
  описывают её честно: 1000 — 1 сектор, 200 — 7, 50 — 8, пусто — 8). Менять вероятности значит
  менять экономику бонусов; предлагаю оставить как есть и не трогать без отдельного решения.
- **Аналитика событий, задания, streak, шаринг купона** — это продукты P2, там нужны решения
  по наградам, а не правки.
